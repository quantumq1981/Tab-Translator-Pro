# UX review — interface & navigation — 2026-11-26

Audience: design. Method: the deployed build (assembled as `pages.yml` does) driven in headless Chromium at
**820 × 1180 (iPad portrait)** and **390 × 844 (iPhone)**, every mode opened, a real Guitar Pro file
(`Steely Dan - Peg.gp4`) loaded, and the code read behind each behaviour. Items marked **verified** were
reproduced in the real app; the rest are direct observations from screenshots and source. The responsive
template recommendation is at the end, with a working mock in `docs/design/workbench-template.html`.

## Ranking

**Impact** = how many users hit it × how badly. **Effort**: S = hours, M = a day or two, L = a week+.
**Contained** = can ship without restructuring the app (✓), touches several panels (◐), or is a shell-level
change (✗).

| # | issue | impact | effort | contained |
|---|---|---|---|---|
| 1 | Tapping any mode tab — even the one you're on — silently deletes your chord edits | **Critical** | S | ✓ |
| 2 | Changing an Audio reading setting silently deletes your chord edits | High | S | ✓ |
| 3 | "Live readout" shows the Manual tab's `C/E` while you look at an unrelated file | High | S | ✓ |
| 4 | Multi-part files open on the first track — often an empty vocal part | High | S | ✓ |
| 5 | ~40 chart controls before the first bar; chart starts ~1,050 px down on a phone | High | M | ◐ |

## Issues

### 1. Tapping a mode tab deletes your chord edits — verified
**What happens.** Every tab's handler is `setMode(m); clearSel()`, and `clearSel` also runs
`setOverrides({})`. Reproduced: open Peg → Rhythm guitar → ✎ Edit, change `F#7` to `F#13` → tap
*MusicXML / GP* again (the tab you are already on) → the edit is gone. No warning, no undo, and the emptied
map is then written to the saved session, so a reload doesn't bring it back.
**Impact.** The worst kind of failure: the user did careful work, did nothing wrong, and lost it without being told.
Every trip to Tuner or Library to check something costs all the corrections on the chart.
**Fix.** Mode switches clear the *selection* only (`selFrets`, `selMidis`, `selKey`); overrides belong to
the chart and are already cleared when a new file loads. One line. Add a regression test.

### 2. Audio reading settings silently drop edits
**What happens.** In the Audio panel, switching Chords/Notes/Drums, toggling Isolate vocals, re-linking a
score, or changing the song key / chord-names setting re-reads the recording and calls `setOverrides({})`.
**Impact.** Users tune settings *after* reviewing chords (it is what the review list invites), so the
order of use guarantees the loss.
**Fix.** When edits exist, keep a snapshot and show an inline notice — "Re-read with the new settings · 6
edits removed · **Undo**" — or re-apply edits whose bar/beat still holds a chord.

### 3. The readout describes a chord the user never chose
**What happens.** In PDF Chart and MusicXML/GP the right-hand (iPad) or lower (phone) panel is titled
*LIVE READOUT* and shows **C/E · Slash chord · 100 %** — the Manual tab's preset — while the user looks
at their own file. On a phone it is a 700 px panel under the chart.
**Impact.** It reads as an analysis of the uploaded file. A wrong-but-confident number is worse than none.
**Fix.** Outside Manual, show an empty state until a chord is tapped: "Tap any chord in the chart to see its
notes." On phone, open it as a bottom sheet on tap instead of a permanent panel.

### 4. Multi-part files open on an empty part
**What happens.** Peg opens on part 0, *Lead vocal*; bars 1–7 are blank. *Harmony (all pitched parts)*
exists as a chip but isn't the default for Guitar Pro (it is for zip/MIDI).
**Impact.** The first impression of a successful import is an empty chart.
**Fix.** Default to Harmony for every multi-part format, or to the first part with block harmony
(`melodicFraction` already measures this). Keep the user's choice once they pick.

### 5. Control density in the chart toolbar
**What happens.** Before the first bar: view switch (5), Edit, numerals, key, simplify, chord names (4),
6/9, spelling, level, arrange, transpose, play + tempo, 9 exports, image, print, paper size, practice,
reference audio — about 40 controls. On a phone the first bar is ~1,050 px down.
**Impact.** The chart — the product — is below the fold; everything has equal weight, so nothing reads as primary.
**Fix.** A primary row of four: **View · Transpose · ▶ Play · Share/Export**. Everything else goes into a
"Chart settings" sheet grouped *Names* (chord names, 6/9, spelling, numerals, key), *Arrangement* (simplify,
level, arrange) and *Practice*. Sticky toolbar while the chart scrolls.

### 6. Navigation model
**What happens.** Nine equal tabs mixing three kinds of thing: ways in (PDF, Scan, GP, Audio, Lyrics), live
tools (Live chords, Tuner) and storage (Library). On a phone they wrap to three rows (~140 px) and scroll
away; from bar 100 of a chart you scroll ~2,500 px back up to switch.
**Impact.** High navigation cost and no clear "where am I" — is Library a place or a mode?
**Fix.** Four destinations: **Open** (all ways in), **Chart** (the current song), **Listen** (Live chords,
Tuner, Audio tools), **Library**. Phone: bottom tab bar. iPad landscape: left rail. Always visible. See the template.

### 7. Inputs organised by file format
**What happens.** A PDF can go to *PDF Chart* (alphaTab tab PDFs), *Scan* (lead sheets, also reads digital
PDFs from their text layer) or neither; GP/MusicXML/MIDI/zip/AlphaTex share one tab; audio another.
**Impact.** The user has to know their file's lineage before the app helps. The engine already identifies
formats by magic bytes (`parseGuitarProOrXML`).
**Fix.** One **Open** drop zone and file picker. Route by content; ask only when it's genuinely ambiguous
("This PDF has tab numbers — read as tab, or read the chord symbols?").

### 8. Instructions before action
**What happens.** Audio mode on a phone: ~400 px of explanatory prose, then Upload, then 15 settings
(chord names, song key, chord changes, Voices (ML), Guitar → Tab, stems …) that do nothing until a file
exists. Scan and MusicXML follow the same pattern.
**Fix.** One-line purpose + the primary button; "How it works" as a disclosure; reveal settings after a
file loads, next to its result.

### 9. Export row named by format
**Fix.** One **Share** menu ordered by intent: *Send to Chord Sheet Maker Pro* (primary, the family
pipeline) · *Print / PDF* · *Image* · *For notation apps* (MusicXML, MIDI, AlphaTex) · *Text* (ChordPro,
ABC) · *Advanced* (CSMPN, ChordSlashML, ListenHub command). Each item gets a one-line description.

### 10. Debug output as interface
**What happens.** "PATH C/D/E/F/G · MUSICXML · …", "CHROMA BITMASK absolute (bit i = pitch-class i)
0b000010010001 = 145 (MSB B → LSB C)", candidate "score 3.00", and a page footer "Engine: pure JS · masks
derived via makeMask() · rotateRight() …".
**Impact.** Noise for musicians; it also undermines confidence ("is this finished?").
**Fix.** Keep the pitch grid (it's useful) labelled "Notes in this chord"; move bit strings, scores and the
engine footer into a "Details" disclosure or a developer setting.

### 11. Touch targets and type
**What happens.** Chips are ~22 px tall (11 px text, 4 px padding), toggles ~30 px; in Audio on a phone 31 of
32 controls are under 32 px. Smallest text 9–10 px; section labels are 10–11 px tracked uppercase.
**Fix.** Under `@media (pointer: coarse)` make every control at least 44 × 44 px (padding, or an invisible
hit area), base text 14 px, labels 12 px. Apple's HIG minimum is 44 pt; Material's is 48 dp.

### 12. State without semantics
**What happens.** Selected = amber border. There are no `role="tablist"`, `aria-selected` or
`aria-pressed` attributes in the UI, and 13 `aria-label`s in ~6,500 lines. Some chips add "✓", most don't.
**Fix.** `aria-pressed` on every toggle chip, `role="tablist"`/`aria-selected` on view switches, a ✓ or fill
change on every selected chip (not colour alone), and a visible `:focus-visible` ring.

### 13. Native alert / confirm
**What happens.** A failed handoff to Chord Sheet Maker Pro and a missing library file use `window.alert`;
deletes use `window.confirm`.
**Fix.** An inline alert with the cause and a next step ("Retry", "Open the library"); deletes as an
immediate action with an **Undo** toast (the library already keeps the bytes until the delete commits).

### 14. "Start fresh" has no safety net
**What happens.** One tap on the restore banner clears the saved session, the chart and every edit.
**Fix.** Do it, then show "Started fresh · **Undo**" for ~8 s, keeping the session bytes until it expires.

### 15. Nested scrolling
**What happens.** The lead sheet sits in its own scroll box (12 of 117 bars visible) inside a page that also
scrolls. On touch this traps the finger: flicks scroll the inner box until it ends, then the page.
**Fix.** Let the chart flow in the page; make the toolbar sticky instead.

### 16. Tab labels and states
**What happens.** "Scan 📷", "Audio 🎵", "Tuner 🎤" have emoji, "PDF Chart" and "MusicXML / GP" don't.
In Chromium, tabs you've visited also show a lighter border than unvisited ones — a third look that means
nothing. The cause wasn't traced; check on Safari.
**Fix.** Use one icon system (or none) and two states only: selected and not.

## Design template recommendation — "Workbench shell" for iPad, tablet and phone

A working, self-contained mock of this shell is in **`docs/design/workbench-template.html`** (also published as a private claude.ai artifact: https://claude.ai/artifact/NXdU5Q6FNweZfKKm5N33xv). Open it and
resize: it shows the three layouts, the bottom sheet, the export menu and the empty readout state. It uses the
app's own palette, so it can drop in.

### Size classes (key off the *window* width, never the device)
iPad Split View and Slide Over can make an iPad window as narrow as a phone, so layout must follow the
window's width, not the device.

| class | window width | layout |
|---|---|---|
| **Compact** | < 600 px (phones, iPad Slide Over / ⅓ split) | Top app bar · single column · **bottom tab bar** · settings, readout and export as **bottom sheets** |
| **Regular** | 600–1023 px (iPad portrait, ½ split, 8–11" tablets) | Top app bar · bottom tab bar or top segmented nav · content · **inspector as a slide-over sheet** from the right (360 px) |
| **Wide** | ≥ 1024 px (iPad landscape, desktop) | **Left nav rail** (76 px) · content · **persistent inspector** (320 px) for readout, voicings and chart settings |

### Navigation
Four destinations: **Open · Chart · Listen · Library**. The current song's name sits in the app bar.
**Chart** is disabled until something is open, and its empty state points to Open.

### Content hierarchy on the Chart screen
1. App bar: song title, key, tempo; **Share** on the right.
2. Sticky toolbar with four controls: View (Chart / Grid / Tab / Notes / Lyrics) · Transpose · ▶ Play · ⋯ Settings.
3. The chart, in the page scroll (no inner scroll box).
4. The inspector (sheet on Compact/Regular, panel on Wide) holds the tapped chord's readout and voicings.

### Tokens (extend the existing "stage" palette; nothing in it changes)
```css
:root {
  /* colour — current palette, named by role */
  --bg: #0b0b0f; --surface-1: #17171d; --surface-2: #22222b; --line: #33333d;
  --text: #efe9dc; --text-dim: #9aa0a6; --brand: #ff6b35; --chord: #ffd9c7;
  --info: #57d1d6; --ok: #98c379; --danger: #e06c75; --warn: #e9a24b;
  --focus: #57d1d6;
  /* type — 6 steps, nothing below 12 */
  --t-xs: 12px; --t-sm: 13px; --t-md: 15px; --t-lg: 18px; --t-xl: 24px; --t-chord: clamp(40px, 9vw, 64px);
  /* space — 4-pt grid */
  --s1: 4px; --s2: 8px; --s3: 12px; --s4: 16px; --s5: 24px; --s6: 32px;
  --r-sm: 6px; --r-md: 10px; --r-lg: 14px; --r-pill: 999px;
  --target: 32px;                      /* fine pointer */
  --safe-b: env(safe-area-inset-bottom, 0px);
}
@media (pointer: coarse) { :root { --target: 44px; } }
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
:focus-visible { outline: 2px solid var(--focus); outline-offset: 2px; }
```

### Components the shell needs (all small; the panels inside stay as they are)
- `AppShell` — size-class aware grid (`grid-template-areas`), uses `100dvh` and safe-area insets.
- `NavBar` (bottom, Compact/Regular) / `NavRail` (Wide) — `role="tablist"`, icon + label, 44 px targets.
- `Sheet` — bottom on Compact, right-hand on Regular, inline panel on Wide; drag handle, focus trap, Esc closes.
- `Toolbar` with overflow — at most 4 visible actions, the rest in `⋯`.
- `Chip` / `Segmented` — `aria-pressed` / `aria-selected`, ✓ on selected, `min-height: var(--target)`.
- `InlineAlert` + `Toast` with **Undo** — replaces `alert` / `confirm`.
- `EmptyState` — one sentence and one action.

### Migration path (no big-bang rewrite)
1. Ship issues 1–4 and 14 (data safety, honest readout).
